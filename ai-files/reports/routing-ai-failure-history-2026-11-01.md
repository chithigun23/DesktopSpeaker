## 2. Root-cause patterns
A. Optimising the gate, not the goal: when a rule blocked progress the rule was relaxed, scoped by name list, or exempted (1-7). DRC 0/0 became the success definition.
B. No independent measurement of the stated goal: every round's report is the author's own gate table; the first measurements of current capacity, angles, return path, spacing came from a later Fable/coordinator script (8-17).
C. Delta-only verification: each round proved "not worse than the previous round" (byte-identical rules, nets unchanged), so inherited defects and creeping regressions were invisible (18-22, 25).
D. Fixes verified against one metric while neighbours silently degraded (clearance, vias, slivers) (19-21).
E. Trusting own or earlier reports and docs: unverified numbers copied forward; reviewer artefacts accepted (23-26).
F. Tool blind spots assumed to be none: KiCad DRC caps, sliver blindness, whole-item neck scope, stale fills, no fab-layer checks, netclass composite names (7, 13-17).

## 3. Strict process rules (what to measure, what is forbidden, what the independent reviewer re-measures)
R-A (rules). Forbidden: relaxing, exempting or narrowing any DRC rule, netclass, rule area or keep-out to clear a violation without a written user decision; forbidden: board-wide or width-based exemptions; rule areas only per named footprint. Every custom rule needs a sentinel test (deliberate violation proves it fires) and a whole-item vs per-piece (1 mm split) DRC. Reviewer re-measures: diff of .kicad_dru/.kicad_pro vs the approved baseline, sentinel run, split-piece DRC.
R-B (goal metrics). Before the first route define measurable acceptance metrics per net class: per-segment current capacity vs design current (width, layer parallel copper, via count x rating, widest-path cuts), % length at 0/45/90, min joint angle, return-path coverage per signal (mm over solid GND / island / void), parallel-run gap per pair, distance of every control/FB/sense pin to any switch node. Forbidden: counting open edges or DRC=0 as quality evidence. Reviewer re-measures all with its own scripts (r7_metrics.py is the template), not the author's gate output.
R-C (regressions). Each round ships a before/after table of ALL metrics (not only the targeted one), including min clearances of touched copper, EP/thermal via counts, decoupling distances, slivers, island pieces. Any worsening of a protected metric is a stop, not a note. Forbidden: running a width/overspec pass without a per-net clearance diff; forbidden: re-basing on an older work copy; build the next round from the project board and run a full footprint/model/pad-net diff.
R-D (inheritance). "Inherited" items must be re-checked against the plan/standard every round, carry an owner and a decision, and count against release. Anything listed inherited twice goes to the user.
R-E (claims). No number in a report without the command that produced it; stale-able claims (counts, distances) carry a date/commit; reviewer must reproduce a sample of at least 10 numbers, plus every number used to justify a PASS. Reviewer measurement artefacts must be cross-checked with a second method (cf. r6k.md:72).
R-F (tool blind spots). Reviewer must, outside KiCad DRC: parse the saved .kicad_pcb, refill zones before any DRC, parse gerbers (mask/paste/via openings), check via-vs-opening distance not centre, sliver test on pours, check netclass assignment of every net by name.
R-G (placement coupling). Do not route past a placement FAIL: decoupling, ground-pin and escape-lane faults are fixed in placement first; routing reports must list nets > 2x MST.
R-H (process). Commit each adopted round; one handover; user decisions recorded the same day.
